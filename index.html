桌面端插件管理（本期最大亮点）：

桌面端此前完全看不到后端插件——原生 Hermes 插件和便携 Agent Plugins v1 包在桌面应用里都是不可见的。现在设置 → 插件页会把它们和桌面端渲染插件列在一起：每行带来源/便携标签、按注册键的启用/禁用开关、实时筛选搜索框，数据源是 plugins.manage 的 nanostore。其他面板自己管的类别（dashboard_auth/*、model-providers/*、platforms/*）在渲染端过滤掉，不污染列表（c86da8397）。

配套改动：插件记录新增一句话描述（Kanban 等内置插件也补了），列表里显示描述而不是原始文件路径；插件区新增"打开插件文件夹"按钮，路径按 config.get 的 profile 解析，仅本地后端可用（44790bc9c）。

底层寻址方式同步修正：plugins.manage 列表行现在携带规范注册键和便携标记——此前启停开关按名字寻址，跨类别目录同名插件会"一开全开"（image_gen/fal 和 video_gen/fal 的 toggles 会互相影响）；改为按键寻址后互不干扰。便携包的进程内 MCP 服务器也并入 enabled_mcp_server_names()，之前它们的工具注册进了 MCP 运行时但没进模型的 schema，等于白注册（a60b492e0）。

便携 Agent Plugins v1 包中带 streamable-http mcp.json 条目的，现在通过 Hermes 现有的 URL-based MCP 客户端真正加载，不再"报告后跳过"（这是 PR #81196 约定好的后续切片）。按 v1 规范 §7.2.1 执行边界规则：URL 必须是绝对 http(s)，不能带用户信息或 fragment；明文 HTTP 仅限 localhost/回环地址（471baea52）。

侧边栏会话列表大改：

会话列表头部原本是"项目/列表"二选一开关，现在变成一个完整菜单：按日期/项目/状态分组，按更新时间/创建时间/状态/token/成本排序，行内可显示 token、成本、PR、profile 或常驻时间戳，按状态/PR/项目/归档筛选。所有选择持久化，一个重置按钮全部还原。细节上：状态分组复用日期分隔线不另造分隔符；按量级排序（token/成本）时不再显示日历（"今天"排在史上最贵会话上面是句假话）；行内元数据和悬停时的 kebab 共用尾部位置，只让最后一项让位；启用筛选时加载深度扩到 300 行（83b8ca1e1）。

会话行现在能显示对应 PR 的状态（open/merged/closed）并可点击跳转：按会话自己的 repo+branch，通过 remote-aware git facade 走后端 gh，每个 repo 一次批量 GraphQL 请求。边界情况都处理了：主干分支不查（Fork PR 共享分支命名空间，查 main 会误标陌生人的 PR）；worktree 会话绑定实际使用的分支（21aaa8b4f）。

未发送的草稿标签页此前全部叫"New session"，一排放开根本分不清谁是谁。现在每个草稿按输入框内容自动命名，用的是后端 derive_title 同一套"首行 + 词边界"规则——草稿显示的名字就是发送后保留的名字（c143ec7f0）。草稿还获得独立的空心状态点，和已定稿会话区分开；消息数为 0 才算草稿，避免把刚恢复的旧会话误标成草稿（5b3a5ccae）。

侧边栏拖拽排序原来只能拖首列 14px 的抓取柄（还只在悬停时出现），现在整行标题都能拖。会话和项目的两种拖拽共用一个按压手势，各自在自己的区域里生效，互不干扰（35b82fdef）。

Windows 更新链路修复集群：

Electron 回滚到 40.10.2：此前 40.10.2 → 40.10.6 的升级（修复 GHSA-r4w5-6pfg-jxp5）在新装 Windows 机器上翻车——40.10.3+ 把 install.js 的解压换成了 @electron-internal/extract-zip，一个 MSVC 编译的原生绑定，没有装 VC++ Redistributable 的机器直接 ERR_DLOPEN_FAILED（8 月 9 日现场报告，全新 VM 复现）。回滚到 40.10.2 修复装机问题；安全影响评估为零——该 CVE 需要遗留的 ProtocolResponse.url API 加 session-partition 隔离，桌面端只用现代 protocol.handle() 且无跨会话隔离，不触碰（bb8280b75）。

更新移交脚本仓库化：桌面端"更新"按钮此前移交给 HERMES_HOME/hermes-setup.exe，而这个 Tauri 二进制没有自更新路径——所有 updater 侧修复只能等新安装包构建签名发布，实际落后 main 数月。8 月 9 日的事故链就是 6 月 4 日的老二进制跑 8 月的仓库：四个独立失败（过期 install.ps1 缓存解析器、标记采用、残留进程清理）全是这个根因。现在改为仓库自带的 Windows 更新移交脚本，不再依赖冻结的 hermes-setup 二进制（92be912d7）。

更新移交全面加固（回应 #82328/#82366 评审 + 补上缺失的进度 GUI）：①失败即停——桌面端 30 秒还活着就 exit 4 不动任何东西，shim 被锁 20 秒就 exit 5，两者都会重新拉起桌面端，用户不会被晾在原地；②真实完成状态——`hermes update` 把桌面端构建失败当非致命（警告但 exit 0）对 CLI 是对的，但对桌面端驱动的更新是撒谎（会拿旧 exe 重启还说"成功"），脚本现在能识别更新输出里的警告、重试一次构建、仍失败就 exit 6 如实上报；③标记所有权——清理时只有自己的 PID 还持有标记才移除，移交伙伴改写过的标记保留认领权；④结果落地——每条退出路径写 .hermes-update-result.json，桌面端启动时消费一次，成功记日志、失败弹真实对话框指向更新日志，过期/畸形结果静默消费，此前失败的分离更新跟"什么都没发生"无法区分；⑤进度界面——脚本从隐藏控制台改成 WinForms 进度窗口（跑马条 + 流式日志），-NoUi 保持无头会话干净（6495ef82f）。

一批更新细节修复：更新进度窗口先抢焦点，重启后的桌面端再接管（952f44f84）；回收残留的桌面端后端进程——桌面端退出后 Python 后端可能存活，venv-holder 保护会误判"Hermes is still running"让更新死锁（8 月 9 日 01:59 和 02:17 两次实测），现在按 PID 判断父进程确实死亡的后端直接回收（826bf9b6d）；每次更新都刷新安装器的 bootstrap-cache 脚本，不再"存在就永远复用"几个月前的 install.ps1（3dcbe9001）；venv 阻塞扫描不再截断命令行——网关的 exe 路径超过 120 字符导致截断后匹配不上豁免规则，桌面端更新每次都误报"Update didn't finish"（0b33ee88e）。

会话连续性加固（gateway 会话身份持久化）：

根因（#82616）：网关会话身份（session_key/chat_id/origin_json）此前是建行后"尽力而为"的单独 UPDATE 写入，重置路径的两次 DB 写都静默吞掉失败（logger.debug / bare print），会话记录读取还忽略写入用的重路由表，重启恢复按 started_at 排候选行且硬拒空行。一次失败写就能让活跃对话流进一个无法路由的孤儿行，而一个几天前的僵尸行握着路由键——网关一重启，对话静默续到僵尸会话上（单机 6 月以来 5 起确认事故）。现在会话身份持久化写入，崩溃重启后对话不中断（d2a4d373e）。

配套修复：会话恢复时遵守 session_reset 策略——此前恢复路径用 updated_at=now 重建路由条目、从不查 _should_reset，自愿开启的空闲/每日重置策略在重启后完全失效，恢复的会话永远显示"刚活跃"、再也无法老化（784f733cf、6e99531c8）；状态库写失败（FTS 损坏或崩溃落在路由发布与建行之间）导致的"缺身份列"孤儿会话，重启后不再续到好几天前的兄弟会话——消息没丢，只是够不到，现在恢复路由身份（c790ed2a5）；每会话待发队列撞 200 条上限且会话库坏掉时，此前把最旧消息弹掉永久丢弃（#78182 静默丢数据），现在运行时落盘缓存，不再丢弃（de0f20ff0）；FTS 索引损坏时主数据写入仍可用（1527a81b5）。

HUD 模式继续完善：

HUD 模式下条栏常常是屏幕上唯一的东西，所以关键状态得显示在条上：工作中显示侧边栏同款旋转弧线（2px 圆角），聚焦时给条边框变色（条贴着窗口边缘，用光环或阴影会被窗口裁掉，直接改边框色）。退出控件从条上挪到输入框上方的空白区，右对齐、聚焦才出现（048907fb6）。

一批 HUD 细节修复：HUD 条从覆盖内容上方抬起，不再压住底层窗口（3d5f17344）；输入框无焦点时退出按钮仍可点击（#82403，11dc61b45）；HUD 固定在打开它的会话上不跳走（#82360，b105a3b05）；HUD 模式开在当前聚焦会话的 profile 上（#82325，124aff0aa）；Linux 上 HUD 保持可点击（da933bf27）。

CLI 状态栏与会话标题修复：

CLI 状态栏现在显示当前会话标题（5a16635f4）。标题生成一批边界修复：模型切换标记不再被当成会话标题（b684cbb09）；自己的脚手架和 TTS 模型不再触发会话命名（53a400320）；cron 和子代理运行不再自动命名会话（cedc933c1）；标题生成器能看到提供商真实模型目录（071eab821）。

Hyprland 版"窗口下方读取"：read_window_below 在 Linux 上走 get-windows（X11 协议），Wayland 拒绝向应用透露别的窗口，XWayland 下只能找到少数旧 X11 客户端、漏掉所有原生 Wayland 窗口——Hyprland 桌面下 HUD 浮在叫不出名字的应用上。现在 HYPRLAND_INSTANCE_SIGNATURE 存在时先问 Hyprland 的命令套接字（j/clients 返回每个窗口的 class/标题/位置/大小/pid/焦点历史），再回退 get-windows（c8318460e）。
