桌面端 HUD 模式（本期最大亮点）：

HUD 模式是桌面端新增的一种悬浮交互形态：一个无边框、透明、始终置顶的小窗口，复用应用自身的真实聊天界面，只改变窗口框架——没有标题栏、没有状态栏、没有窗格树。窗口底部是输入框，上方消息带以渐隐方式显示：回合进行中或输入框聚焦时保持可见，空闲后逐渐淡出，鼠标可以穿透到背后的应用。用户可以通过标题栏按钮或快捷键（macOS 为 ⌘⇧H）随时进入 HUD 模式（e8b83f37c、6a01b429d）。

HUD 里的会话交接做得比较完整：因为网关把一个会话的事件流绑定到唯一 socket，HUD 里开始的一轮对话只会在 HUD 里流动，关闭 HUD 时主窗口会自动恢复该会话、重建传输并接续进行中的回合，不会丢上下文（7b0dbd224）。

HUD 模式下 agent 能感知自己的悬浮状态：桌面端给 HUD 提交打上 surface: 'hud' 标记，网关把它转成每回合的提示，指向新加的 read_window_below 工具——agent 可以查询 Hermes 窗口底下是哪个应用窗口（应用名、标题、位置，仅元数据不读像素），回答"你下面是什么窗口""帮我查天气"这类问题时直接针对用户正在用的应用操作（e24bac49f、406501fd9、f22ae7292）。工具调用前会先检查 agent 自己的 schema，没有 computer_use 或 read_window_below 的会话不会被指向调不了的工具。

HUD 消息带改用 macOS 原生毛玻璃（vibrancy）渲染，三档渐隐：刚落地时半显示供扫一眼、聚焦时提升到可读、空闲后收起滑到输入框后面。只有空闲记录才会淡出，运行中的回合或等待用户回复时保持打开（4500b4391）。从其他标签页唤出 HUD 时会正确重定向到当前查看的会话（f444e0c5e），一批 HUD 细节修复同步合入（窗口尺寸、面板显隐、鼠标穿透边界、对话框下不穿透等：0e260b3c8、6ada733f9、c5332b2f8、843c3abcc、f9860b050、717b49c08、48d672e49、ba4456ab0、f03fc4684）。

图像与视频生成模型扩充（FAL + Krea）：

图像生成新增 FAL Nano Banana 2 模型（2b16a6b03）。视频端新增 Seedance 2.5、MiniMax H3、Seedance 2.0 Mini、FLUX 3、Grok Imagine 1.5、Gemini Omni Flash（仅图生视频）等新端点；图像端新增 Seedream 5.0 Pro（含编辑）与 Lite、Ideogram V4 instant/fast、Qwen Image 3（含编辑）、MAI Image 2.5 Pro、Nano Banana 2 Lite（含编辑）、Recraft V4.1，全部 18 个新端点通过真实 payload 在 fal.run 上实测通过（70c6cf8e7）。

放大策略调整：所有原生输出低于约 2MP 的图像模型默认开启放大（upscale=True），用户不会悄悄拿到低清图——FAL 目录 16 个模型翻转默认值（klein、z-image、nano-banana pro/2/2-lite、gpt-image 1.5/2、ideogram v3/v4、recraft v4/v4.1、qwen image/3、krea-2 medium、MAI 2.5 pro 等）；Krea 插件按模型设置默认（medium/medium-turbo 开启、large 关闭）。原生高分辨率模型（Seedream 5 Pro/Lite、Krea 2 Large）保持关闭，避免为已够大的输出付费。upscale 参数仍保留按次覆盖（false=快速草稿，true=强制放大）（66ea4e686）。image_generate / video_generate 同时支持可选放大通道（137960c9a）。

Windows 编码问题集群修复（高感知修复季）：

auth 凭据读取改用 UTF-8：之前凭据存储文件按系统代码页（Windows 上是 cp1252）解码，任何非 ASCII 字节（中文/emoji 标签、带重音符号的显示名）都会抛 UnicodeDecodeError，最坏情况是 _load_auth_store 的宽泛 except 把文件改名 .corrupt 后返回空存储——下次启动静默清空所有提供商凭据。现已统一 UTF-8 读取（762f1c588），其余 auth.json 读取点同步覆盖（2fda6a384、2e227d74f）。

剪贴板读取改 base64 传输：PowerShell 的 Get-Clipboard 输出系统 ANSI 代码页文本（CP1252/CP936），Node 按 UTF-8 读会把中文/emoji 弄乱；现在读路径也像写路径一样先 base64 编码再传（9dcce84c3）。

working_diff 在 Windows 上按 UTF-8 解码 git 输出：之前用系统代码页（cp932）解码，非 ASCII 文件名直接抛 UnicodeDecodeError，破坏"git 失败也不抛异常"的契约；改为 UTF-8 + errors=replace，遗留的 cp932 编码内容降级为替换字符而不是崩溃（26eeb8568）。

邮件抓取不再被畸形字符集打断：未知字符集标签（QQ 邮箱的 unknown-8bit 占位符、拼写错误的编码名）会从 bytes.decode 抛 LookupError，中断整个批次抓取；因为 UID 在抓取前就标记为已读，崩溃等于永久丢掉整批消息。现在有字符集别名表（unknown-8bit→utf-8、gb2312/gbk→gb18030 等）+ utf-8/latin-1 逐级回退，畸形 RFC 2047 头降级为原始字符串（65f407184）。

孤代理项（lone surrogate）崩溃在三个关口统一拦截：finalize_turn 在模型文本离开会话循环时清理、网关聊天面边界清理（Telegram utf16_len、Signal 格式化）、run_conversation 遍历完整 api_kwargs 清理工具描述——覆盖 oneshot 输出、NIM/任意提供商响应和所有投递消费者（566b5b16a、8b799fa77）。

二进制文件检测改在字节层做：之前通过终端传输采样文本判断（head -c 1000 采样经文本层解码），多字节字符在字节 1000 处被截断会变成 U+FFFD 替换符，_is_likely_binary 把任何含 U+FFFD 的文本都当成二进制——合法的中文/emoji 文本被标记为不可读。现在按 base64 传输的字节内容分类，不再依赖有损文本层（e40315d53）。

.env 读取统一 utf-8-sig：BOM 不再吞掉第一个键（aa1fac980、ece678db9、b76498ba0、7fef76a6c），json_parse 容忍 UTF-8 BOM（f2feb6f37）。更新过程的交互提示也处理了 UnicodeDecodeError（70957591f、1bb261251），cron 投递输出文件按 UTF-8 写入（4af7f0550）。

会话即时命名与记录管理：

会话标题生成从"第一轮回复后"提前到"开场"：原来标题在第一轮回复时才生成，一个回合是多次工具调用而非一次往返，实测 p50 要 151 秒、p90 要 1212 秒才等到标题，且失败或被中断的回合永远没有标题。现在拆成两步：先用确定性规则从用户开场消息生成标题、在模型运行前写入，再调用一次小模型升级；响应约束为 JSON 对象无需剥离前言，斜杠命令按用户实际意图命名而非命令名本身（f726090d4）。标题加来源追踪防止互相覆盖（5566379f5），起标题模型从提供商实时目录解析（perf，e358eaf44）。

记录导出上限可配置：sessions.max_resume_messages / sessions.max_export_messages（默认 20000，0 关闭）替代硬编码的硬拒绝；CLI 的 sessions export 保护从累计改为按会话，备份大量小会话的全库备份不再被卡；错误提示指向配置项而非（仅针对损坏的）修复命令（f0794640f）。超大会话记录不再耗尽内存（c750d5354）。

办公文档技能 clean-room 重写（许可证合规）：

bundled 的 docx、xlsx、powerpoint、pdf 四个技能原本改编自 Anthropic 的文档技能，带有专有 LICENSE.txt（禁止衍生、禁止再分发），被 SkillEvaluator 一级扫描标记为关键许可问题。现在全部替换为 clean-room 重写：由隔离子代理仅凭库知识（python-docx、openpyxl、python-pptx、pypdf/reportlab/pdfplumber，均为 MIT/BSD 许可）从零编写，明确禁止阅读旧技能内容或 anthropics/skills，会话记录保留作为来源证明（51570f4da）。功能对齐持续补齐（fad88cf13）。另新增 8 个技能：competitor-news-monitor（竞品新闻监控）、social-media-content-calendar（社媒内容日历）、weekly-review-planning（周复盘规划）、product-price-monitor（产品价格监控）、meeting-action-items（会议行动项）、google-workspace-daily-brief（Google Workspace 每日简报）、github-issue-to-pr（Issue 转 PR）、email-inbox-triage（收件箱分类）（309c9bbbe、5cc4c2d30、6eaea9c70、56d9e75db、8dcebded5、9e2d37250、29783634b、ebb242d81）。
